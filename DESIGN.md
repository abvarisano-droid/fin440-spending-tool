# DESIGN.md

Spend Shadow visual spec. Builders apply this; they do not edit this file, `.streamlit/config.toml`, `styles.css`, or `core/ui.py`.

SITE: Spend Shadow (FIN 440)
ONE SIGNATURE MOMENT: On Shadow portfolio, the second KPI ("In {ticker} it'd be worth") is the only oversized number in the app. Everything else stays at the type scale below.
WEBSITE MAP: top nav (Upload, Spending breakdown, Shadow portfolio, Risk & CAPM, Timing test, Roth calculator, Proof). No sidebar. Wide layout. Seven labels scroll sideways on a phone; Streamlit's `>>` control is the overflow.

Chosen direction (v2, 2026-11-18): **the Ashton Capes site system**, taken from `ashton-capes-site/assets/styles.css` (editorial layer) and `assets/tokens.css`, so the class project matches Ashton's portfolio site. Warm white, deep forest, Geist throughout, pill buttons, rounded white cards with soft shadows, small uppercase labels. v1 (the Fraunces "editorial ledger" below) is retired; its layouts, keys and rules stay.

## Experience rules (customer-experience pass, verified at 1280px and 390px)

- **Captions are full opacity.** Streamlit fades `stCaptionContainer` to 60%, which drops muted text below AA; CSS resets it.
- **Charts are transparent** on their white card (set in `ui.chart` and CSS), never a grey box.
- **Legends wrap into columns** (2 per row, set on each color encoding because Streamlit's chart theme overrides legend config), so nothing runs off a phone.
- **Chart toolbar hidden on touch screens**, where it covered card titles and could not be hovered away.
- **Money in tables uses the `dollar` format** (`$6,963.81`, `-$219.61`); shares use one decimal; money inputs that are whole dollars use `%.0f`.
- **Proof table leads with Result** (`✓ Pass`), so a phone shows the verdict first; differences read `$0.00` / `-$1,779.75`, not scientific notation; the method for each check lives in an expander list.
- **KPI wells share one height per row on desktop**; on a phone they stack at natural height.
- **In-page links are ghost pills**; on a phone the Upload actions stack full width.
- **Motion:** content rises in (8px, 420ms, light stagger) only on navigation, because Streamlit keeps elements mounted between reruns (verified: no flicker when a setting changes); stale elements fade to 0.6 instead of snapping; inputs get the site's soft focus halo; cards, wells, pills and buttons lift 2-3px on fine-pointer hover; every button presses to 0.98. All of it is off under `prefers-reduced-motion`.

## Motion

- Easing (site): `cubic-bezier(0.2, 0.7, 0.2, 1)`; cards 300ms, buttons lift 2px on hover
- Card lift: 220ms, `translateY(-2px)`, only inside `@media (hover: hover) and (pointer: fine)` so a tap on a phone does not leave a stuck hover
- Button hover (fine pointer): background snaps to `accent-hover`; motion is 160ms transform/opacity only
- Button press (touch / coarse pointer): 160ms, `scale(0.98)` and opacity 0.88
- `touch-action: manipulation` on buttons (no extra tap delay). Tap highlight is a light pine wash
- Page transition: Streamlit native rerun (no custom)
- Properties: transform and opacity only
- Reduced motion: `@media (prefers-reduced-motion: reduce)` sets transition, transform, and `scroll-behavior` to none

No scroll libraries, no grain overlay, no parallax. Streamlit reruns make cinematic scroll a mismatch. The app is usable on a phone: columns wrap at 640px, top nav can scroll sideways, tables and charts scroll inside their card if they overflow.

## Page layouts

Keyed containers already exist. CSS targets `.st-key-<key>`. Keep these keys stable.

### 1. Upload (`app_pages/upload.py`)

Order, top to bottom:

1. Title: "Upload your transactions". Caption: session-only privacy line.
2. **`upload_source`**: file uploader, then secondary "Use sample data" button on the same block (surface fill, pine text: same as Clear data). After a real file, "Load transactions" is the only pine primary. Sample is still one click for the fictional CSV.
3. **`column_mapper`** (only after a real file): bordered card, subheader "Check the columns", three columns (date/description | amount mode | sign). Preview table `raw_preview` directly under the card. Primary "Load transactions" under the preview.
4. **`loaded_summary`**: bordered card after a successful load. Subheader "Loaded". Nested **`loaded_kpis`**: three metrics (Purchases, Total spent, Date range). Caption with source name. Two actions in a horizontal row: page link to spending, "Clear data" as a secondary button.

Empty: only title, caption, and `upload_source`. No mapper, no summary.

### 2. Spending breakdown (`app_pages/spending.py`)

Order:

1. Title. Course caption (`:material/school:` FIN 440 / BKM chapters). Then "Totals include only purchases unless you turn on transfers." Toggle "Include transfers and card payments" immediately under that (filter, not a card).
2. **`spend_kpis`**: four metrics in one row: Total spent, Per month (avg), Discretionary, Discretionary share. The row container is unbordered; each metric uses `st.metric(border=True)` as a paper well.
3. Two-column row **3:2**: **`chart_by_category`** (bar, dollars on x, category on y) | **`table_by_category`** (totals + share progress).
4. **`chart_by_month`**: full-width stacked bars by month.
5. **`top_merchants`**: top 10 table, full width.
6. Expander **`all_tx`**: editable category column. Collapsed by default.

### 3. Shadow portfolio (`app_pages/shadow.py`)

This page holds the signature moment.

1. Title. Course caption (Ch 2, 5, 7). Then: fractional shares, dividend-adjusted, no fees or taxes.
2. **`shadow_controls`**: bordered card. Ticker (1/3) and category multiselect (2/3).
3. **`shadow_kpis`**: four metrics: You spent, **In {ticker} it'd be worth** (signature: 40px Geist, fairway if gain / brick if loss), Annualized (XIRR), Priced as of. The second metric is the only oversized number in the product.
4. Skip-count `st.info` only when purchases sit after the latest close.
5. **`chart_shadow`**: step-after line, spent vs shadow value. Spent series uses `blue` `#2C4A6E`. Shadow series uses `orange` `#B45309`.
6. **`shadow_compare`**: full-width card under the signature chart. Title "Same purchases, four portfolios". 2 to 4 buy-and-hold lines on one plot (defaults: 100% VOO, 60/40 VOO/BND, 100% BND, 100% QQQ from `core.portfolios.PRESETS`). Color field `name` uses `ui.PORTFOLIO_COLORS`. This is a comparison, not a second signature: KPI values on this card stay at the 28px scale. Call `ui.chart`.
7. Expander **`shadow_ledger`**: per-purchase table, collapsed.
8. Disclaimer caption under the expander.

### 4. Roth IRA calculator (`app_pages/roth.py`)

1. Title. Course caption (Ch 5). Then: real return = today's dollars; income limits unchecked.
2. **`roth_inputs`**: bordered card, three columns. Age/start | contribution source | rate, convention, due, cap. Radio for contribution source; slider appears in-column when redirecting discretionary spending.
3. **`roth_kpis`**: three metrics: Balance at {age}, You put in, Growth. Growth uses the green delta color when positive.
4. Cap `st.info` only when the monthly amount exceeds the 2026 limit.
5. **`chart_roth`**: stacked area, contributions (`blue`) under growth (`green`).
6. **`roth_mc_controls`**: bordered card under the deterministic chart. Title "With uncertain returns". Method (normal vs bootstrap), annual vol (normal) or a caption that bootstrap uses fund history, optional target balance, run size. Keep it on one row that wraps; this is TVM under uncertainty, not a second hero.
7. **`chart_roth_fan`**: percentile fan. Outer band p5-p95 (`#CFE0D4` fill, `#3E7A52` 1px stroke), inner band p25-p75 (`#8FBF7A`), median p50 fairway line `#17603A`. X is age, Y is balance. Call `ui.chart_fan` with `simulate_roth(...)["percentiles"]`.
8. **`roth_mc_kpis`**: Median (p50), Bad case (p5), Odds of the target. 28px Geist, same wells. No 40px number here.
9. Expander **`roth_math`**: closed-form FV, then the year table. Collapsed.

### 5. Risk & CAPM (`app_pages/risk.py`, new)

Class topic: risk/return, CAPM, SML. Needs loaded transactions. Market series is SPY.

1. Title: "Risk and CAPM". Course caption (Ch 2, 5, 6, 7, 9; not 4 or 8). Then: volatility and beta come from unit value (deposits do not look like returns); prices and the T-bill are Yahoo only.
2. **`risk_window`**: horizontal radio, not a card. "Your purchase dates" (default) vs "Last 5 years of fund history". Purchase dates replay buys via `unit_value`. History uses a daily-rebalanced mix (`lab.constant_mix_index`) so a six-month sample is not the only read. Prefer history for the presentation.
3. **`risk_kpis`**: five wells for the default portfolio (100% VOO vs SPY): Vol, Sharpe, Max drawdown, Beta, Alpha. Wrap on a phone. Alpha uses green/brick delta coloring via a signed string. Caption under the row: T-bill yield, EAR, day count. `st.info` when the window is under 252 trading days.
4. Two-column row **1:1**: **`chart_risk_return`** | **`chart_sml`**.
   - Scatter: x = annualized vol, y = annualized return, one dot per portfolio plus SPY, color `name`. Axis percents. Call `ui.chart_risk_return`.
   - SML: pine line of `risk.sml_line` (x = beta, y = expected return). Dots are each portfolio's realized return at its beta. Call `ui.chart_sml`. If realized SPY return is below the T-bill, the line slopes down: the explainer must say that is a short-window realized premium, not CAPM's expected premium, and point at fund history.
5. **`risk_table`**: bordered card, title "All portfolios". Dataframe widget key `risk_stats` (a container and a widget cannot share a key).
6. **`risk_explainer`**: bordered card, body type. CAPM `E[R] = rf + beta (E[Rm] - rf)`. A dot above the line earned more than CAPM asked for over this sample. SPY sits on the line (beta 1, alpha 0).

### 6. Timing test (`app_pages/timing.py`, new)

Class topic: market efficiency, behavioral finance. Needs loaded transactions. Default ticker matches Shadow (VOO).

1. Title: "Timing test". Course caption (Ch 11, 12). Then: if prices already reflect what is knowable, the dates you spent should look like luck.
2. **`timing_controls`**: bordered card. Ticker (1/3) and category multiselect (2/3), same split as `shadow_controls`.
3. **`timing_kpis`**: Your dates in {ticker}, Median random dates, Your percentile. Value is `37th` (a percentile, not rank 37 of 1,000). Label: "Your percentile, of 1,000 shuffles". Neutral color; luck is not a gain/loss.
4. **`chart_timing_hist`**: histogram of the 1,000 shuffled end values (`#C9D0B0` bars, `#5A7D5C` 1px stroke). Pine rule at the actual value, muted dashed rule at the median shuffle. Call `ui.chart_histogram`.
5. **`timing_explainer`**: bordered card. 5th to 95th percentile is consistent with luck. Give the min/max of the 1,000 shuffles in the body (small steady purchases barely move). Lump-sum-on-day-one in the body, not as a fourth KPI.

### 7. Proof (`app_pages/proof.py`, new)

Class topic: validation. Works with sample data; still `require_transactions` so every check has a CSV.

1. Title: "Proof". Caption: key numbers are checked live against a second computation that does not use the app's own code; the workbook lets a grader redo the math in Excel with real formulas. The page lists what the live checks cover vs what the final audit recomputed by hand.
2. **`proof_checks`**: bordered card, title "Live checks". Lead line: "{n} of {m} checks pass" on this data. Dataframe widget key `proof_table` (a container and a widget cannot share a key). Columns: Check, App, Independent, Difference, Result (Pass or Fail), How (header "How it's checked"). Tabular nums.
3. **`proof_download`**: unbordered block. Primary pine download button, key `proof_xlsx`, label "Download the cross-check workbook". Caption: built in memory; sheets Roth (FV), Shadow (purchases, shares, value), Risk (SLOPE beta, volatility, T-bill, Sharpe).
4. **`proof_process`**: expander, collapsed, key `proof_process`. Title "How AI built this, and how we kept it honest". Drawn from HANDOFF (no transaction rows, no account numbers).

## Component rules (`core/ui.py`)

Signatures stay stable: `section(key, title=None, border=True)`, `kpi_row(key, items)`, `chart(c, key=None)`.

- `section`: keyed `st.container`. Bordered card by default (`upload_source` passes `border=False`). Geist 500 h3 when `title` is set.
- `kpi_row`: keyed container, equal `st.columns`, each `st.metric(..., border=True)`. CSS sets Geist 500 28px values with -0.045em tracking. The shadow signature metric is wrapped as `.st-key-shadow_signature` (gain, fairway) or `.st-key-shadow_signature_down` (loss, brick), 40px / 2.5rem. Roth growth (third `roth_kpis` value) is green.
- `chart`: Altair theme `spend_shadow` (also registered globally): legend bottom, no view stroke, axis `#6E675C`, grid `#E6DDD0`, view clip off so long category labels stay whole. Field `series`: domain Spent (cumulative) then Value in {ticker}, range `SPENT` / `SHADOW`. Field `part`: Contributions / Growth in `CONTRIBUTIONS` / `GROWTH`. Field `category`: pinned `CATEGORY_COLORS` (14 distinct fills); the scale domain is only categories present in the frame, so empty ones stay out of the legend. If `category` is on x or y and color is unset, `ui.chart` fills the bars and hides the legend (the axis already names them). Field `name` or `portfolio`: `PORTFOLIO_COLORS` (VOO orange, 60/40 blue, BND muted, QQQ pine, SPY violet). Named constants: `ui.SPENT`, `ui.SHADOW`, `ui.CONTRIBUTIONS`, `ui.GROWTH`, `ui.PORTFOLIO_COLORS`.
- Extra helpers (Phase 7): `chart_fan(percentiles_df, key=...)`, `chart_histogram(values, markers=[...], key=...)`, `chart_risk_return(df, key=...)`, `chart_sml(line_df, points_df, key=...)`. Fan outer and histogram bars take a `#5A7D5C` stroke. Pages pass engine frames; they do not restyle these.
- Primary button: pine fill, white label, 4px radius. Secondary / "Use sample data" / "Clear data": surface fill, pine text, 1px border. Download (`proof_xlsx`) is primary. In-page `stPageLink` is 44px tall like buttons.
- `st.caption` for helper copy. Course lines with `:material/school:` are pine 500 (`[aria-label="school icon"]`); other captions stay muted. `st.info` for the empty-upload pointer and skip/cap notices only.
- Tables: header `surface-tint`, hairline borders, tabular nums.
