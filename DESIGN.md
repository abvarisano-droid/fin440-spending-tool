SITE: Spend Shadow (FIN 440)
ONE SIGNATURE MOMENT: On Shadow portfolio, the second KPI ("In {ticker} it'd be worth") is the only oversized number in the app and the only dark tile (the v8 hero widget: deep teal-ink glass, light serif number). Everything else stays at the type scale below.

**v4 redesign (2026-11-19, after Ashton's review of v3).** Same tokens, rebuilt from a ranked critique (HANDOFF). `styles.css` was rewritten from scratch as one ordered layer (v3 had three stacked layers overriding each other). ## Experience rules (customer-experience pass, verified at 1280px and 390px)

- **Captions are full opacity.** Streamlit fades `stCaptionContainer` to 60%, which drops muted text below AA; CSS resets it.
- **Charts are transparent** on their glass card (set in `ui.chart` and CSS), never a grey box.
- **Legends wrap into columns** (2 per row on each color encoding, because Streamlit's chart theme overrides legend config), so nothing runs off a phone.
- **Age axes start at the first age in the data** (no zero, no nice rounding), so the Roth charts do not open on an empty band from 20 to 22. `ui.chart` applies this to any chart whose x field is `age`; `ui.chart_fan` sets it directly.
- **Chart toolbar hidden on touch screens**, where it covered card titles and could not be hovered away.
- **Money in tables uses the `dollar` format** (`$6,963.81`, `-$219.61`); shares use one decimal; money inputs that are whole dollars use `%.0f`.
- **Wide tables put the key numbers first and pin their label column**, and a swipe hint caption (`swipe_hint_{proof,compare,merchants}`) sits under each one. The hints show only at 640px and below; desktop tables fit, so CSS hides them above that.
- **Proof table leads with Result** (`✓ Pass`), so a phone shows the verdict first; differences read `$0.00` / `-$1,779.75`, not scientific notation; the method for each check lives in an expander list.
- **KPI wells share one height per row on desktop**; on a phone they stack at natural height.
- **In-page links are ghost pills**; on a phone the Upload actions stack full width.
- **The phone menu says Menu.** Streamlit's collapsed-nav button ships as a bare double arrow with an empty `aria-label`; CSS frames it as a ghost pill and adds a "Menu" label (which also gives it an accessible name).
- **Motion:** content rises in only on navigation, because Streamlit keeps elements mounted between reruns (verified: no flicker when a setting changes); stale elements fade to 0.6 instead of snapping; inputs get the site's soft focus halo; cards and KPI tiles lift on fine-pointer hover; every button presses to 0.98. Numbers in Motion below. All of it is off under `prefers-reduced-motion`.

## Motion

Numbers as shipped in `styles.css`:

- Easing: `cubic-bezier(0.2, 0.8, 0.2, 1)` (`--ss-ease`) everywhere
- Page enter: `ss-rise`, 420ms, from `translateY(8px)` and opacity 0; stagger 30ms per block, capped at 150ms
- Card lift (fine pointer only, inside `@media (hover: hover) and (pointer: fine)`): 300ms, `translateY(-3px)` plus the lift shadow
- KPI tile lift (fine pointer): 300ms, `translateY(-2px)`
- Glass sheen on card hover: opacity 0 to 1, 160ms
- Primary pill hover (fine pointer): 200ms, `translateY(-2px)` and a deeper glow; ghost pills change edge and fill only
- Press (every pointer; touch also drops opacity to 0.88): `scale(0.98)`
- Stale rerun fade: opacity to 0.6 over 250ms
- Focus halo on inputs: 200ms, 3px teal ring at 28% (buttons and page links 35%)
- `touch-action: manipulation` on buttons, page links, the dropzone and the header Menu pill. Tap highlight is a light teal wash
- Properties: transform and opacity only for motion; colors and shadows change without moving layout
- Reduced motion: `@media (prefers-reduced-motion: reduce)` turns off transitions, hover and press transforms, the entrance animation, the sheen transition and smooth scrolling

No scroll libraries, no grain overlay, no parallax. Streamlit reruns make cinematic scroll a mismatch. The app is usable on a phone: columns wrap at 640px, the nav becomes a menu, tables and charts scroll inside their card if they overflow.

## Component rules (`core/ui.py`)

Signatures stay stable: `section(key, title=None, border=True)`, `kpi_row(key, items)`, `chart(c, key=None)`, `chart_fan(...)`.

- `page_header(title, *, course=None, lede=None)` (new in v4): keyed container `page_head` with `st.title`, the course chip (`course` is the chapter text; the helper adds `:material/school:`) and the lede caption. Pages adopt it through a builder request; until then CSS styles the plain title and captions the same way.

- `section`: keyed `st.container`. Glass card by default (`upload_source` passes `border=False`). Serif 400 h3 when `title` is set.
- `kpi_row`: keyed container, equal `st.columns`, each `st.metric(..., border=True)`. CSS makes each a glass tile (top-aligned, 112px min) with serif 400 34px values; labels and deltas wrap, values never truncate. The shadow signature metric is wrapped as `.st-key-shadow_signature` (gain: `#7FF0E8`) or `.st-key-shadow_signature_down` (loss: `#FFB4A6`) and drawn as the dark hero tile, 46px. Roth growth (third `roth_kpis` value) is teal.
- `chart`: Altair theme `spend_shadow` (also registered globally): legend on top (left, horizontal, 2 columns; line charts key with a short stroke, others with a dot), no view stroke, axis labels muted `#4F5752` 12px with 500 titles, y grid `#E3E9E8` only (no x grid), no axis domain or ticks except a hairline x domain, lines 2.25px with round caps, view clip off so long category labels stay whole, background transparent on the glass card. Field `series`: domain Spent (cumulative) then Value in {ticker}, range `SPENT` (`#B0603A`) / `SHADOW` (`#0A716C`). Field `part`: Contributions / Growth in `CONTRIBUTIONS` / `GROWTH`. Field `category`: pinned `CATEGORY_COLORS` (14 distinct fills); the scale domain is only categories present in the frame, so empty ones stay out of the legend. Custom categories (renamed or split on Spending) follow the built-ins in the domain, in order of first appearance, filled from `CUSTOM_CATEGORY_COLORS` (cerulean `#1B8FB5`, orange `#E0832F`, indigo `#3D3FA8`, wine `#7E1F3B`, emerald `#2A9D5C`, cycling past five). If `category` is on x or y, color is unset and the mark is a bar, `ui.chart` draws one teal `#0A716C` fill with 5px rounded bar ends and no legend (a ranked list: the axis already names each bar). Stacked category bars get a 1px white seam between segments. Field `name` or `portfolio`: `PORTFOLIO_COLORS` (VOO teal, 60/40 blue, BND muted, SCHD plum, SPY ink). An x field named `age` gets a tight scale (no zero, no nice). Named constants: `ui.SPENT`, `ui.SHADOW`, `ui.CONTRIBUTIONS`, `ui.GROWTH`, `ui.ACCENT`, `ui.MUTED`, `ui.PORTFOLIO_COLORS`, `ui.MARKET_NAMES`. Color encodings set a 2-column wrapping legend.
- Extra helpers: `chart_fan(percentiles_df, key=...)` (Roth). `chart_histogram`, `chart_risk_return` and `chart_sml` stay in `ui.py` for the kept engines but no page calls them since the Risk and Timing test pages were removed (2026-11-19). Pages pass engine frames; they do not restyle these.
- Primary button: cyan `#34E0D6` pill with `#0A1420` ink, 600. "Use sample data" is primary until a file is chosen. Secondary / "Use sample data" after a file / "Clear data" / in-page `stPageLink`: frosted ghost pills, `#C4C9C3` edge, ink text, 44px tall. Download (`proof_xlsx`) is primary.
- `st.pills` (`shadow_chip`): glass pills, 38px (44px phone); the picked one fills cyan with ink. Multiselect chips: cyan 20% glass, teal 28% edge, ink text. `roth_mode` radio: a segmented control (grey track, the selected option a raised white pill; full width on a phone); other radios stay native, with a 2px `#7A817B` ring when unselected.
